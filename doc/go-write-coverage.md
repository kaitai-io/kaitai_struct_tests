# Go writer boundary coverage

`spec/go/specwrite/coverage.json` identifies handwritten contracts which need
more precise assertions than an eager whole-object roundtrip. `run-go-write`
includes them in the same suite and annotates its XML and JSON reports with
their category, reason, and membership in the Java/Python writer reference set.
The additional `COVERAGE` summary counts top-level fixtures once, independently
of subtests. The ordinary `SUMMARY` counts test results, not roundtrip coverage.
The `CORPUS` summary is the parity gate: it deduplicates generated tests and
their stronger handwritten contracts by canonical fixture name.

The manifest accounts for the complete writer corpus:

- 287 primary reference fixtures: 285 KST-backed fixtures shared with the Java
  and Python writer suites, plus the handwritten-only
  `opaque_external_type_02_parent` and `opaque_with_param` fixtures;
- 35 additional KSTs: 13 automatic roundtrips, 11 source-declared expected
  parse failures, four handwritten boundaries, two negative-generation
  templates, and five shared unsupported multibyte-terminator schemas.

The primary gate reports one status per fixture even when a generated parse
test and one or more table-driven writer contracts exercise the same schema.
The expected primary result is 264 passing fixtures and 23 expected-parse
skips. Raw Go test and subtest totals remain visible in `SUMMARY`, but are not
used as fixture parity counts.

The converter defaults to a strict production mode. It validates the status of
every named primary and additional fixture, the exact per-category counts, the
five intentionally non-generated fixtures, and permits only the explicitly
named non-corpus harness tests. A missing, unexpected, or incorrectly
classified fixture makes `run-go-write` exit nonzero even when `go test` itself
passed. Partial reporter unit tests must explicitly set
`GO_WRITE_COVERAGE_MODE=partial`; that mode is not used by the production gate.

- `manual_serialization_contract`: bounded recursive instances, intentional lazy
  conversion errors, or a deliberately partial read completed before writing.
- `unsupported_serialization_semantics`: a passing negative contract which
  confirms the current rejection. It does **not** count as a successful
  roundtrip or an expected parse skip. The prefix-sensitive debug fixture reads
  lengths `[3,2,1]`, but consistency checks see the final parent collection size
  and reject the child lengths. The manifest records the exact removal condition.
- `negative_generation`: the two `str_encodings_escaping_*` KST headers explicitly
  declare manual templates for deliberately invalid encodings. They are not
  automatic successful-roundtrip inputs. Each original spelling is tested
  independently in ordinary and read-write compiler modes, preserving diagnostic
  characters. These tests require the staged compiler at the usual sibling
  `compiler` location; set `KSC` to override the launcher path.
- `shared_unsupported_generation`: the five UTF-16 multibyte-terminator schemas
  are an inherited Go, Java, and Python writer-generation limitation, deferred
  by compiler commit `8df0955fe581558fdd7561e38f0c6e0f12fff133`.
  They are outside the 287-fixture reference set and are reported as not
  generated, never as passing roundtrips or issue-backed exclusions.

Removing the autogenerated-marker comment makes a Go writer test handwritten.
The KST translator preserves that production test both in default generated
output and with `--force`; regeneration cannot replace these contracts with the
generic eager oracle. `build-formats-go-write` lists the two manual negative
templates separately when selecting the default successful-generation corpus.
Explicitly requesting an invalid schema still invokes the compiler and fails.

`expr_io_ternary` is also preserved by name. Its selected stream contains bytes
that the schema does not model, so generic whole-dump equality is invalid: the
handwritten contract verifies the original derived values, exact fresh output,
and the exact canonical rewrite where unmodeled bytes become zero. The
generated-name delegator and the boundary test are counted as one fixture.

`io_local_var` uses the real `full256.bin` input to verify complete-file bytes
for a parsed empty positioned child, parent mutation, fresh construction, and a
partial positioned overlay. Unwritten overlay holes remain owned by the parent.
The two opaque fixtures likewise use exact bytes, initialized parent/root
topology, and reparse checks.

The portable Java/Python handwritten writer behaviors are executable in Go.
Two reference-language null-state distinctions are intentionally not modeled:
Go strings are non-nullable, and nil and empty slices are equivalent for a
zero-repeat serialization. Java's six duplicate random-access-file capacity
paths have no distinct Go fixed-file writer backend; the same byte/position
semantics are covered with the bounded Go writer.

No issue-backed exclusion is claimed for these tests. In particular, the old
C++ debug-array ownership issue does not track prefix-sensitive writer checks.
